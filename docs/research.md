# 提速巡线车的编码器测速与 PI 调参调研

日期：2026-07-27  
对象：`firmware/WHEELTEC_C07A_CAR_SPEEDUP`  
问题：低速巡线时左右实际速度曾频繁归零；滑动测速后连续性改善，但长时间运行仍可能出现顿挫。

## 结论

1. 低速、低分辨率编码器不应仅用一个很短周期内的脉冲数测速。行业实现通常延长计数积分时间，或在低速时改用“相邻脉冲的时间间隔”测速。
2. 当前采用的 `4 × 5 ms = 20 ms` 滑动计数窗口是合理的第一步：仍每 5 ms 更新，但每个编码器计数对应的速度分辨率从约 `66.3 mm/s` 降为约 `16.6 mm/s`。
3. 测速窗口和低通滤波引入了额外延迟，因此旧 PI 参数不能直接视为最优。长时间后顿挫加重时，优先怀疑积分项 `Ki` 过强、输出饱和后的积分恢复，以及电池/摩擦变化；不要先提高速度。
4. 本车的 `Kp/Ki` 不应每 5 ms 自适应修改。先得到稳定的一组固定参数；只有实测证明直线、弯道和原地转向需要明显不同的控制强度时，才在**状态切换**时使用少数几组固定参数。

## 1. 当前工程与问题量化

| 项目 | 当前值 |
| --- | --- |
| 控制周期 | 5 ms（200 Hz） |
| 轮周长 | 约 0.2413 m |
| 编码器 CPR | 728 |
| 直线/弯道目标速度 | 90 / 75 mm/s |
| 滑动测速窗口 | 4 帧，即 20 ms |
| 速度低通 | `SPEED_FILTER_ALPHA = 0.4` |
| 固件默认 PI | `Kp = 400`，`Ki = 300`（`control.c`） |
| 当前实车测试值 | 用户报告 `Ki = 250`；若通过上位机修改，该值仅保存在运行时 RAM，复位后恢复默认值 |

单周期测速时：

```text
每个编码器计数 / 5 ms = 0.2413 × 200 / 728 ≈ 66.3 mm/s
90 mm/s 约为 1.36 个计数 / 5 ms
75 mm/s 约为 1.13 个计数 / 5 ms
```

所以匀速时也可能读到 0 个计数；这解释了左右 `Current_Encoder` 同时归零而车并未真的停住的现象。20 ms 窗口满载后每计数约为 `16.6 mm/s`，更适合当前速度范围。

## 2. 公开实现的共同做法

### 2.1 按速度选择测速方法

TI 的 C2000 eQEP 资料将测速分为两类：中高速用固定时间窗内的位置增量 `ΔX / T`；低速用相邻位置事件间的时间 `ΔT` 计算 `ΔX / ΔT`。TI 也明确建议在低速和中高速之间设置边界，选择不同的测量方式。[TI eQEP 低速/高速测速说明](https://e2e.ti.com/support/microcontrollers/c2000/f/c2000-microcontrollers-forum/1500833/tms320f28375d-frequency-calculation-eqep)

对本项目的启示：20 ms 滑动窗是固定时间窗的低风险改进；若 75 mm/s 以下仍有明显量化，再考虑在 GPIO 中断中记录脉冲时间戳，并在低速时切换到周期法。不要把两种算法在同一帧简单平均。

Pololu 在低速平衡车的编码器实践中也指出，定时读取编码器必须留出足够时间累计“至少几个计数”，否则速度估计不可靠。[Pololu：Balboa 编码器与低速速度估计](https://www.pololu.com/blog/665/how-to-make-a-balboa-robot-balance-part-3-encoders)

### 2.2 滤波用于抑制测量噪声，但会引入相位延迟

TI/MathWorks 的速度测量模块将速度由位置差分得到，并提供低通滤波；滤波常数越强，输出越平滑、响应越慢。[C2000 Speed Measurement 文档](https://www.mathworks.com/help/ti-c2000/ref/c2000speedmeasurement.html)

对本项目的启示：滑动窗和 `alpha=0.4` 已同时平滑测速；若继续大幅降低 `alpha`，会让 PI 看到更晚的速度，反而可能形成慢摆。优先观察 20 ms 窗口的实车效果，暂不同时再加大滤波。

### 2.3 PI 必须处理饱和、积分累积和状态切换

Microchip 的电机 PI 控制文档指出：输出达到物理限幅后，持续误差会导致积分 windup；应限制积分，并在使能/模式切换前做合适初始化，以避免顿挫。[Microchip PI 控制器的 anti-windup 与初始化](https://www.microchip.com/content/dam/mchp/documents/FPGA/ProductDocuments/UserGuides/ip_cores/directcores/speed_id_iq_pi_controller_ug.pdf)

Microchip 的电机控制应用笔记还给出 back-calculation anti-windup：通过“未限幅输出与实际限幅输出之差”反向约束积分量。[Microchip AN2757](https://ww1.microchip.com/downloads/en/AppNotes/Sensored-Encoder-Based%29-Field-Oriented-Control-of-Three-Phase-%20Permanent-Magnet-Synchronous-DS00002757A.pdf)

对本项目的启示：现有代码已在急弯/丢线切换时重置 PI 历史量；若完成 `Ki` 调整后仍出现“运行越久越明显”的顿挫，下一步应增加显式 anti-windup，而不是持续盲目降低 `Kp`。

## 3. 本车的 PI 参数如何受影响

| 因素 | 对 Kp 的影响 | 对 Ki 的影响 |
| --- | --- | --- |
| 编码器量化、测速噪声 | 噪声越大，Kp 应越小，否则 PWM 高频跳变 | 过大也会随误差正负反复累积 |
| 滑动窗与低通延迟 | 延迟增加后，过大的 Kp 更易产生振荡 | Ki 过大时更容易慢摆、越跑越明显 |
| 电池电压下降、地面阻力、升温 | 主要影响响应速度和左右不一致 | 需要一定 Ki 消除长期速度误差，但不能过强 |
| 目标速度/转向 | 转向时两轮目标持续变化，过大 Kp 会追逐瞬态 | 低速轮和原地转向更容易积分累积 |
| PWM 限幅 | Kp 大时更容易撞到限幅 | 限幅时间越长，越需要 anti-windup |

本工程是增量式 PI：

```text
Pwm[k] = Pwm[k-1] + Kp × (e[k] - e[k-1]) + Ki × e[k]
```

这里的 `Ki` 是“每 5 ms 更新一次”的离散增益，不是可直接照搬其他项目的连续时间 `Ki`。因此网上或其他底盘给出的具体数字没有可比性；只能借鉴测量、限幅和调参流程。

## 4. 推荐实车调参流程

前提：每次只改一个量；直线和弯道分开记录；确认两轮实际速度不再频繁归零。

1. **固定当前速度**：保持 90/75 mm/s，不提速；记录 2 m 直线连续运行和完整一圈的实际速度、PWM、是否顿挫。
2. **先验证 Ki=250**：这是从 300 的温和下调。若长时间顿挫减轻且末段不再加重，保留 250。
3. **若仍越跑越顿**：只调 `Ki`，按 `250 → 200 → 150`。每个值至少跑完整一圈；选择“末段最平稳且低电量下仍能跟速”的最小 Ki。
4. **若实际速度已平滑但 PWM 仍高频往复**：保持选定的 Ki，只调 `Kp`，按 `400 → 300 → 250`。选择能跟住目标、又不产生快速抖动的最小 Kp。
5. **若速度长期低于目标且 PWM 未到 7800**：小步提高 Ki，或加入前馈 PWM；不要先提高 Kp。
6. **若 PWM 经常到 ±7800 或急弯后才顿挫**：记录限幅时间，优先实现显式 anti-windup；状态切换处继续保留 PI reset。

## 5. 是否需要动态 Kp/Ki

当前阶段：**不需要每帧动态调参**。传感器和速度估计刚完成改造，在线自适应会把测量误差、赛道扰动和真实参数变化混在一起，难以复现问题。

后续满足以下条件时，才考虑“增益调度”：

- 已确定一组直线固定参数能连续跑完整圈；
- 已确定急弯/原地转向的顿挫来自轮速目标突变，而非测速归零；
- 同一组参数无法同时满足直线和原地转向。

实现方式应是按状态使用固定参数集，例如 `FOLLOW` 与 `SHARP_TURN` 各一组，并只在状态边沿切换、同时重置 PI 历史量；不要根据单帧灰度或单帧编码器值修改增益。

## 6. 下一步决策

- 若 Ki=250 后整圈连贯：保持当前参数，再小幅提速。
- 若 Ki=250 后末段顿挫仍明显：下一次只改为 Ki=200。
- 若 Ki=200 后仍有“累计变差”，检查 PWM 是否长期接近限幅；若是，实施 anti-windup。
- 若实际速度仍偶尔归零：扩大测速窗至 6 帧（30 ms）前，先评估周期法测速；窗口再长会增加转向时的反馈延迟。
