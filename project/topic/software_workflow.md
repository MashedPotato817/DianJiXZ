# H 题软件工作流

## 1. 目标与边界

本工作流服务于 2026 TI 杯 H 题“车载平衡滚球运动控制系统”。软件目标是让 MSPM0G3507 底盘沿红色闭环路线行驶的同时，依据 K230 相机测得的小球位置控制摆杆舵机，使小球稳定在杆中心或指定位置。

软件底座为 `project/mspm0/`：它继承 `firmware/WHEELTEC_C07A_CAR` 的 Keil 工程、SysConfig、TB6612 电机、编码器、8 路灰度巡线、OLED 和 5 ms 控制中断。`firmware/Medicine_Cart` 仅参考模块边界和状态机组织，不复用其业务逻辑或引脚配置。

本文件不把“代码已编写”当作“实车已验证”。所有涉及舵机、K230、灰度和底盘的项目都必须按第 7 节完成实测验收。

## 2. 当前软件结构

```text
project/mspm0/
├── Control/
│   ├── control.c/h        # 底盘速度闭环、灰度巡线、5 ms 控制中断
│   ├── ball_control.c/h   # 小球位置闭环，输出摆杆目标角度
│   └── ball_task.c/h      # H 题任务状态机
├── Hardware/
│   ├── motor.c/h          # TB6612 双电机
│   ├── encoder.c/h        # 左右编码器
│   ├── servo.c/h          # 舵机角度命令、限幅、后续 PWM 映射
│   └── k230_link.c/h      # K230 小球位置数据接口
├── empty.syscfg           # 唯一允许修改引脚和外设配置的位置
└── keil/                  # MSPM0G3507 Keil 工程
```

当前新增模块已通过 Keil 编译；但尚未接入实际舵机 PWM、K230 UART 收包或实车闭环。

| --- | --- | --- | --- |

## 4. 必须先冻结的接口

### 4.1 K230 到 MSPM0 的数据契约

在写 UART 解帧前，视觉和主控共同确认以下项目，并将最终定义写入 `Hardware/k230_link.h`：

1. 坐标轴：沿摆杆方向以杆中心 `O` 为零点；右侧为正、左侧为负。
2. 单位：MSPM0 接收值统一为 mm，避免将像素直接参与控制。
3. 有效性：小球被可靠检测时 `valid=1`；丢球、遮挡或置信度不足时 `valid=0`。
4. 时间：每帧携带递增时间戳或序号，主控以此判断帧延迟和丢帧。
5. 串口帧：帧头、长度、载荷、校验和、帧率必须固定；禁止依赖串口一次刚好收到完整帧。
6. 故障策略：连续超时或 `valid=0` 时，主控将舵机回机械安全中位并停车。

推荐先用容易抓包的 ASCII 帧完成首轮联调，例如：

```text
$K230,BALL,<x_mm>,<valid>,<seq>#
```

性能稳定后，如 ASCII 帧率或解析耗时成为瓶颈，再切换为带 CRC 的二进制帧；切换前必须保留抓包样例和兼容期。

### 4.2 舵机接口

硬件同学必须提供：舵机型号、信号线 MCU 引脚、供电方案、机械中位、可用转角、最小/中位/最大脉宽。软件收到这些信息后：

1. 在 `empty.syscfg` 增加一个独立的 50 Hz TimerA PWM 通道。
2. 用 TI SysConfig 重新生成 `ti_msp_dl_config.c/h`，不手改生成文件。
3. 在 `Servo_ApplyHardware()` 完成“角度 → 脉宽 → 比较值”映射。
4. 先抬空摆杆验证中位、方向和机械限位，再允许启用小球控制。

## 5. 分阶段开发任务

### 阶段 0：工程基线（已完成）

- [x] 创建 `project/mspm0` 独立工程。
- [x] 保留原底盘 SysConfig 与 Keil 构建链路。
- [x] 新增舵机、K230、小球控制和任务状态机模块骨架。
- [x] Keil 编译通过：`0 Error(s), 0 Warning(s)`。

### 阶段 1：K230 视觉与串口链路

1. 在 K230 实机确认所用 CanMV 固件与相机驱动可用；不要用桌面 Python 的导入结果替代实机验证。
2. 用静态球、缓慢移动球、不同光照分别采集视频，验证球心识别稳定性。
3. 标定“像素坐标 → 摆杆毫米坐标”关系，记录标定距离、相机位置、镜头畸变处理方式和误差。
4. 实现固定格式发送、MSPM0 解帧、校验、帧序号/时间戳和 100 ms 内的超时检测。
5. OLED 或串口持续显示 `x_mm`、`valid`、帧率和超时次数。

验收：主控连续 60 秒收到稳定数据；人为遮挡小球时能在规定超时内置 `valid=0`，不产生随机位置跳变。

### 阶段 2：舵机单元测试

1. 完成 50 Hz PWM 配置和角度映射。
2. 依次输出中位、正小角度、负小角度，确认“软件正方向”与小球运动正方向一致。
3. 测量舵机实际可用角度和摆杆机械限位，不以标称参数代替实测值。
4. 在无球状态下验证掉电、复位、视觉丢失时均回安全中位。

验收：连续执行 100 次中位—正角—中位—负角循环，无碰撞、无超限和无明显抖动。

### 阶段 3：静止控球（题目第 3 项）

1. 先将目标固定在 `+5 cm`，使用低增益 PD 控制并记录误差曲线。
2. 再切换到 `-5 cm`，检查方向、超调、稳定时间和稳态误差。
3. 加入位置死区、导数低通滤波、舵机角度限幅与视觉超时停机。
4. 参数按“单次只改一个量”记录：`Kp` 决定响应强度，`Kd` 抑制摆动，死区抑制视觉噪声。

验收：按题目要求，稳定时间小于 5 s，目标点附近最大误差小于 1 cm。测试记录必须包含目标、初始位置、参数、视频或曲线。

### 阶段 4：底盘与滚球并行（题目第 4、5 项）

1. 先关闭滚球控制，仅验证低速直线巡线和停车；不要把底盘故障误判为 PID 问题。
2. 在直线低速行驶中启用控球，逐步提升速度。
3. 分别测试进入半圆、半圆中段、出半圆的视觉误差与舵机输出。
4. 建立底盘速度、曲率与小球目标补偿的预留接口；未验证前默认目标为杆中心。
5. 最后完成 A 到 B、单圈 A 到 A 的计时和停车逻辑。

验收：车辆投影不出轨；小球位置误差满足题目第 4、5 项的 1 cm 要求；每次运行保存时间和异常原因。

### 阶段 5：指定位置保持（题目第 6 项）

1. 将目标位置参数化，不在代码中散落常数。
2. 增加按键/串口选择目标位置、复位和急停。
3. 复用视觉、舵机和超时保护，测试全程保持指定点。

验收：单圈时间小于 30 s，小球在指定位置附近的最大误差小于 1 cm。

## 6. 任务状态机

`ball_task` 按以下状态推进，任何故障都可转入 `BALL_TASK_FAULT`：

```text
IDLE
 ├─ 仅底盘单圈 ──────────────> CHASSIS_LAP
 ├─ 静止控球 ───────────────> HOLD_CENTER
 ├─ 单圈并保持中心 ─────────> LAP_HOLD_CENTER
 └─ 单圈并保持指定位置 ─────> LAP_HOLD_TARGET

任意状态 ──视觉超时/巡线失效/急停──> FAULT
FAULT ──人工复位且输入恢复─────────> IDLE
```

每个状态必须定义：进入动作、周期动作、完成条件、超时条件、故障动作。禁止仅靠延时堆叠实现题目流程。

## 7. 联调顺序与记录要求

严格按以下顺序联调；前一步未通过不得进入后一步：

1. Keil 编译和烧录。
2. 电机方向、编码器方向、5 ms 速度闭环。
3. 灰度通道顺序、低速巡线、停车点识别。
4. K230 识别、标定和 UART 抓包。
5. 舵机中位、方向和限位。
6. 静止控球。
7. 低速直线控球。
8. A 到 B、单圈中心保持、单圈指定位置保持。

每次实测至少记录：提交号、固件版本、K230 版本、舵机参数、控制参数、场地条件、执行结果、失败现象和原始视频/数据位置。硬件异常（单轮不动、电源掉压、机械卡滞）与软件控制问题必须分开记录。
