## B. 设计过度 / 可等价简化（结构性）

### B1. `ball_control.c` 十状态手调状态机（600 行，44 宏）—— 最大简化点
- **现象**：OFF/CAPTURE/ACCEL/RUN/BRAKE/PASS/EDGE/HOLD/LOST/FAULT 十相，含三级定时升档（20/24/28°）+ `accel_scale` 误差缩放、运动确认、预测制动（v²/2a）、受控过零（PASS：pass_target=起始误差 20%、3~8mm、150ms、2~6°阻尼）、非线性中心阻尼（2~8°随速度）等。
- **问题**：这些微状态大多是为补偿"原始反馈差、无轨迹规划"而累积的补丁（文档第 12~21 节可见 20 多轮逐个打补丁的痕迹）。
- **简化方案**（来自 `project/research/H题第三项_算法调研_20260731/03_控制算法理论.md`）：引入**双积分状态观测器** + **降带宽位置 PD**（Kp 0.24→~0.012）+ **梯形速度规划参考轨迹**后，状态机可塌缩为**「逼近（轨迹整形）+ 驻留（条件积分/踢动）」两态**，ACCEL/RUN/BRAKE/PASS 大段可删。
- **收益**：600 → 约 150 行（省 ~450 行），且收敛更快、过冲更小。
- **风险**：属重构，需按调研方案重做并重调参；**建议在 fix Agent 当前调参稳定后作为独立重构项**，不要与在调的功能混在一起改。

### B2. trim 在线学习近关闭但保留 5 个参数
- `ball_control.h`：`TRIM_KI=0.02`、`LEARN_ERROR=4`、`LEARN_VELOCITY=8`、`MAX_STEP=0.03`、`MIN/MAX=15/165`。
- 效果已趋近 0（文档第 21 节主动收窄）。要么按调研改"上电自校准 + 固定 trim"，要么删掉学习只留固定 trim，能去掉 ~5 宏 + ~30 行。

### B3. `debug_telemetry.c` 新增事件环形缓冲（`$E` 事件行）
- 8 槽 ISR/主循环双端 ring buffer + `strncpy`。功能合理（事件不阻塞、不丢），但对低频按键/任务事件略重。若只在联调期用，可退化为直接 printf。**低优先**，不急着动。
