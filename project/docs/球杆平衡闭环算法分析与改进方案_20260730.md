# 球杆平衡闭环算法分析与改进方案

> 最后更新：2026-07-30 21:11

日期：2026-07-30
状态：分析完成，尚未实施本方案

## 1. 背景与当前问题

当前上层小球系统由 K230 输出小球横向位置 `x_mm`，MSPM0 根据位置控制 PA8 舵机，从而改变摆杆倾角。约定如下：

- 目标位置为 `0 mm`（画面中心）；右侧为正。
- 实测：降低 PWM 会使小球向右移动、`x_mm` 增大；因此球偏右时应提高 PWM，使其向左回归。
- 舵机使用 `0~180°` 绝对角度，`90°` 为中位，对应 `1600 us`；正常控制暂限 `90±20°`。
- 齿轮—摇杆传动比例约为：舵机转 `180°`，摆杆角度变化约 `11°`。

现象：小球在视野内（例如 `+30 mm`）可能停住，舵机虽有抖动，小球却不产生可见位移。

当前控制器为直接位置 PD：

```text
舵机偏移角 = Kp × (x - target) + Kd × d(x - target)/dt
```

当前 `Kp=0.24 °/mm`。当 `x=+30 mm` 且球静止时，输出约为 `+7.2°` 舵机偏移，折算到摆杆仅约 `0.44°`。该倾角可能不足以克服小球静摩擦、齿隙和传动阻力；同时小球静止时 D 项近似为零，控制输出不会继续积累。

## 2. 参考工程的控制算法

参考：`reference/球杆平衡控制系统/WHEELTEC_APP/RobotControl_task.c`。

参考工程采用带角度反馈的串级控制：

```text
目标小球位置
    ↓
位置 PD（50 Hz，输出目标杆角度）
    ↓
角度 P（100 Hz，输出步进频率）
    ↓
步进电机 → 摆杆
    ↑             ↑
小球位置       杆角度 ADC
```

其主要策略：

| 环节 | 参考实现 | 目的 |
|---|---|---|
| 位置外环 | `Kp=0.2`、`Ki=0`、`Kd=0.2`，50 Hz | 位置误差决定目标倾角；D 项抑制摆动 |
| D 项滤波 | 一阶低通，截止频率 2 Hz | 抑制测距噪声被微分放大 |
| 角度内环 | P 控制，100 Hz | 快速实现外环要求的摆杆角度 |
| 输出保护 | 死区、最小有效频率、最大频率 | 防止低频抖动、执行器失效和机构碰撞 |
| 调试顺序 | 传感器监视 → 方向点动 → 角度环 → 串级 | 先验证符号与执行器，再闭环 |
| 启动保护 | 传感器稳定期、PID 状态复位 | 防止启动瞬间由旧数据造成冲击 |

参考工程位置环同样刻意保持 `Ki=0`：球杆系统天然不稳定，位置积分会在球未响应时持续累积，随后容易形成过冲或振荡。

## 3. 对当前 K230 + 舵机系统的适用性

PA8 舵机内部已有位置闭环，可以近似视为参考工程的“角度内环”；但当前 MSPM0 无法读取摆杆实际角度。因此不应照搬步进频率、ADC 零点和参考 PID 数值。

可迁移的算法结构为：

```text
K230 位置帧 → 位置滤波/速度估计 → 位置 PD → 目标舵机角度
                                         ↓
                         限幅 + 静摩擦脱困 + 舵机内部位置环
```

不可直接迁移的部分：

- 参考工程的角度 ADC 内环：本系统没有摆杆角度传感器。
- 步进电机的最小频率和频率死区：舵机接口是绝对角度/PWM，不是速度指令。
- 参考工程的数值参数：执行器、机构、传感器和传动比均不同。

## 4. 建议的下一版控制策略

### 4.1 保持位置 PD，暂不加入常规积分

保留当前误差符号：

```text
error = x_mm - target_x_mm
servo_offset = Kp × error + Kd × velocity
```

其中 `velocity` 为滤波后的 `d(error)/dt`。球向右运动时速度为正，输出提高 PWM，有助于提前把球拉回左侧，方向与实测一致。

不建议先直接加 `Ki`。应先解决“小输出无法克服静摩擦”的问题；积分会在识别丢失、机构卡滞或杆已到限位时积累，风险较高。

### 4.2 为速度估计增加一阶低通

K230 的位置帧有检测噪声和不均匀到达间隔，直接差分容易使舵机高频抖动。建议将速度改为：

```text
raw_velocity = (error[k] - error[k-1]) / dt
velocity[k] = velocity[k-1] + alpha × (raw_velocity - velocity[k-1])
```

初始可将等效截止频率设在 `2~4 Hz`，之后以日志和实车响应调整。位置 PD 只在新 K230 帧到达时更新，不能在 5 ms 控制周期内对同一帧重复计算 D 项。

### 4.3 增加受限的静摩擦脱困

当小球偏离中心且持续没有运动时，使用最小有效舵机偏移，而不是无限增加积分：

```text
触发条件：|error| ≥ 8 mm，且 |filtered_velocity| ≤ 4 mm/s，持续 300~500 ms
动作：    保持当前 PD 方向，但 |servo_offset| 不低于 BREAKAWAY_OFFSET_DEG
退出：    检测到球重新移动、进入小死区、K230 数据无效或超时
```

建议从 `BREAKAWAY_OFFSET_DEG=12°` 开始实测。它对应约 `0.73°` 摆杆变化，明显大于 `+30 mm` 时原 PD 的约 `0.44°`，但仍远低于已确认安全的 `90±80°` 舵机范围。该值是待整定起点，不是最终标定值。

### 4.4 分级限幅与安全状态

| 状态 | 建议行为 |
|---|---|
| 正常有效位置 | PD + 滤波 D，常规限幅先试 `±30°` |
| 静摩擦脱困 | 在安全方向施加最小有效偏移；仍受 `±30°` 常规上限保护 |
| K230 帧无效、普通丢失或链路超时 | 回到 `90°` 中位，清空控制历史 |
| 明确左右出画面 | 保留现有边缘恢复状态机，不与常规脱困混用 |
| 复位或重新启用闭环 | 清空速度滤波、静止计时、D 项和边缘恢复状态 |

`±30°` 仅为第一档验证值。若该值仍无法让小球启动，再基于实际 PWM、摆杆角度和球速逐档提高；不应直接把正常闭环上限设为边缘恢复的 `±75°`。

## 5. 实施前后的验证方法

### 5.1 先验证执行器和方向

1. 停止闭环，将舵机依次命令为 `60°、75°、90°、105°、120°`。
2. 观察摆杆实际倾角与 PWM 是否单调对应，并确认 `PWM 增加 → 小球向左加速`。
3. 记录每个角度下小球从静止开始滚动所需时间，找出最小有效舵机偏移。

### 5.2 再验证闭环

在 `x≈+30 mm` 与 `x≈-30 mm` 两侧分别静置小球，各重复至少 5 次：

| 指标 | 通过条件 |
|---|---|
| 方向 | 两侧都向中心回归，不向外侧加速 |
| 脱困 | 卡住后在设定等待时间内开始移动 |
| 收敛 | 进入中心附近后无持续大幅摆动 |
| 执行器 | 无长时间顶在限位，无异常高频抖动 |
| 视觉异常 | `LS/HD` 或帧超时不会触发持续偏转 |

### 5.3 必须记录的遥测字段

后续 K230 文本日志只能证明视觉测得的位置，不能证明 MSPM0 实际输出。因此应在 MSPM0 OLED/串口增加至少以下字段：

```text
x_mm, valid, filtered_velocity_mm_s,
pd_offset_deg, breakaway_active,
servo_target_deg, servo_pulse_us
```

这样才能区分以下三类问题：控制器给力不足、舵机/传动未响应、或小球视觉位置误判。

## 6. 推荐实施顺序

1. 先添加仅用于观测的速度滤波、PD 输出、舵机角度/PWM 与脱困状态遥测。
2. 以 `±20°`、无脱困运行，确认滤波后的 D 项不会带来额外抖动。
3. 加入静摩擦脱困，初值 `12°`，先做单侧 `+30 mm` 测试。
4. 验证左右方向对称性后，再逐步将常规限幅试至 `±30°`。
5. 收集日志后再决定是否需要极弱、可泄放的偏置积分；它不应作为第一选择。

## 7. K230 日志数据分析与新增隐患

本节分析 `project/k230/log/` 中两份运行日志。日志仅记录 K230 应用层的终端输出，**不能证明 MSPM0 实际接收、执行了每一帧，也不能证明舵机或小球的物理响应**。

### 7.1 数据概览

| 日志文件 | 记录时长 | UART 序号范围 | 估算发送速率 | UART 有效/无效日志行 | 最长连续 UART 无效段 |
|---|---:|---:|---:|---:|---:|
| `20180101_000007_uart.txt` | 157 s | 10–2519 | 15.98 Hz | 166 / 119 | 约 27.6 s |
| `20180101_002307_uart.txt` | 842 s | 10–13499 | 16.02 Hz | 1087 / 499 | 约 66.8 s |

配置的 `SEND_PERIOD_MS=50` 对应理想发送频率约 `20 Hz`，而两份实际日志均约为 `16 Hz`。这说明完整的双通道取图、圆检测、预览显示、串口处理和文件日志共同决定了有效位置更新率。`16 Hz` 并非不能闭环，但它决定位置外环和速度估计不能按 200 Hz 的 MSPM0 定时周期来理解。

### 7.2 `vision` 与 `uart` 数值不同不等于串口错误

日志中的一行同时打印两类数据：

```text
vision: ...      # 当前循环、当前画面的检测结果
uart: ... seq=N  # 最近一次满足 SEND_PERIOD_MS 后已发送的帧
```

两者不是同一时刻采样。代码在发送周期到达时才更新 `tx_x_mm`、`tx_valid` 和 `seq`，而日志按 `LOG_PERIOD_FRAMES` 单独触发。因此测试中可见：

- 第一份日志的两者位置差最大为 `6.5 mm`；
- 第二份日志的两者位置差最大为 `9.7 mm`；
- 第二份日志中约有少量“当前视觉有效、最近 UART 帧无效”或相反的组合。

这首先是**采样时刻不同**的结果，不能据此判断 UART 丢包。不过它会误导调参：屏幕/文本上看到的当前 `vision x_mm` 并不总是 MSPM0 正在控制的值。后续应在发送分支内额外记录 `TX` 行，至少带有 `tx_x_mm`、`tx_valid`、`edge`、`seq` 和 `ticks_ms`；预览则明确标记为 `vision`，不要声称两者逐帧一致。

### 7.3 丢失持续时间远大于当前恢复时间

第二份日志有 `499` 条 UART 无效记录，其中：

- 左边缘方向 `edge=-1`：72 条；
- 右边缘方向 `edge=+1`：410 条；
- 普通丢失 `edge=0`：17 条。

也就是说，无效状态中约 `97%` 被判为“靠近画面边缘后丢失”。其中连续无效段最长约 `66.8 s`，另有约 `45.7 s`、`40.0 s` 等长段。

现有 MSPM0 边缘恢复超时为 `1 s`，超时后回中位并锁定，直到重新获得有效帧。这一策略对机构保护是正确的；但若恢复动作无法在 1 秒内把球拉回视野，系统将在长时间丢失中保持中位，无法自动恢复。日志证明这种情况至少曾出现过，因此需要在后续实测中单独记录：边缘触发时刻、恢复舵机角度、1 秒后的实际位置/帧状态和最终恢复时刻。

### 7.4 边缘方向不是物理位置的直接测量

`edge_direction` 的依据是“最后一次可靠球心是否落在图像左右各 24 px 内”，随后连续丢失达到阈值才置为 `-1/+1`。它不是小球真实到达机械端点的确认。

潜在隐患：近边缘的反光、遮挡、圆检测跳变或 ROI 截断，也可能造成同样的边缘判定。如果直接据此使用较大的恢复角度，可能在误判时施加错误的恢复动作。建议补充日志字段：`last_valid_center_x_px`、`lost_streak`、`edge_direction`、恢复状态与恢复持续时间；在未看到这些证据前，不应仅凭 `edge` 数量继续提高恢复幅度。

### 7.5 短暂漏检仍可能对 MSPM0 保持“有效”

当前配置为 `LOST_FRAMES=3`：短暂找不到圆时，K230 保留最后一次可靠 `x_mm`，在达到连续丢失阈值前仍可能发送 `valid=1`。日志中存在：

- 第一份：26 条“当前 `source=none`，但最近 UART 帧 `valid=1`”；最长可见约 `1.7 s`；
- 第二份：38 条同类记录；最长可见约 `0.6 s`。

由于日志本身异步，这些时长不能直接等同于每帧实际保持时间；但它说明控制器可能在视觉暂失时继续使用旧位置。对稳定运行这能降低瞬时抖动，对快速运动则可能形成过时控制量。速度 D 项和静摩擦脱困逻辑必须在无新有效观测时冻结或复位，不能把保持的旧位置当作连续新样本。

### 7.6 端到端链路证据不足

两份 K230 日志各只出现一次 `MSPM0 BALL frame acknowledged`。这与当前 MSPM0 代码一致：它只在收到首个合法 BALL 帧时回一次 ACK，并不逐帧确认。现有 ASCII 帧也没有校验和。

因此当前日志能证明：K230 曾成功与 MSPM0 建链、MSPM0 持续发出心跳；但不能量化长期的接收溢出、解析错误、序号跳变或帧内容损坏。后续需从 MSPM0 输出或 OLED 记录下列字段：

```text
last_seq, valid_frames, parse_errors, rx_overruns, timed_out,
x_mm, valid, edge, servo_target_deg, servo_pulse_us
```

特别是 `last_seq` 应与 K230 的 `seq` 对照；这样才能区分“视觉未检出”“K230 未发送”“UART 未收到”和“MSPM0 收到但未执行”。

### 7.7 标定与日志性能风险

- 两份日志都明确处于 `temporary uncalibrated UART position mode`；当前配置仍为 `CALIBRATION_READY=False`、`UART_ALLOW_UNCALIBRATED=True`。因此日志中的 `x_mm` 可用于控制方向、趋势和时序分析，不能作为实际位置精度或闭环指标。
- K230 系统时钟显示为 `2018-01-01`，仅适合分析单个文件内的相对顺序，不能与 MSPM0、手机或示波器的真实时间直接关联。
- 日志函数每次打印都会 `flush()` 文件；第二份日志还记录了 1633 次 MSPM0 心跳（约 1.94 次/s）。SD 卡写入和频繁终端输出可能引入额外帧间隔抖动，是“实际约 16 Hz”的待验证影响因素，而非已证实根因。性能测试时应提供关闭文件日志或批量刷新模式，并对比发送速率。

## 8. 基于日志的实施优先级

在加入更激进的控制增益前，推荐按下列顺序补足可观测性：

1. 在 K230 发送处记录真实 `TX` 帧及单调 `ticks_ms`，将其与预览检测行分开。
2. 在 MSPM0 输出接收诊断、最新序号、`x/valid/edge`、PD 输出、舵机角度/PWM、脱困状态。
3. 用同一测试同时录 K230 与 MSPM0 日志，确认 16 Hz 更新率、端到端延迟和序号连续性。
4. 先验证最长 1 秒的边缘恢复是否能可靠回到视野；若不能，再设计分级恢复，而不是盲目延长或加大单次恢复。
5. 在关闭/降频日志后复测发送速率，再决定 D 项滤波截止频率与静摩擦脱困等待时间。

## 9. 结论

当前问题更像“执行到摆杆的有效倾角不足”，而不是单纯的 D 参数不足。参考工程验证了球杆系统应以位置 PD 为主、D 项提供阻尼、并用限幅和分阶段测试保障安全。日志进一步说明，在提高增益前必须先区分当前画面、真实发送帧、MSPM0 接收帧和实际舵机输出。结合本系统没有杆角度反馈、但舵机自带位置环的特点，下一步应实现“滤波 PD + 有条件静摩擦脱困 + 完整端到端遥测”，而不是直接引入普通积分或大幅提高全部场景下的比例增益。
