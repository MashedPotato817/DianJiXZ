# ESP32-C3 巡线遥测接收接口

MSPM0 通过 **UART1** 主循环节拍发送巡线遥测帧，ESP32-C3 super-mini 接收并转发（串口/WiFi/日志皆可）。本文档描述帧格式与解析约定，供 ESP32 端固件实现。

## 物理链路

| 项 | 值 |
|---|---|
| MSPM0 侧 | UART1（`fputc` 已重定向到 `UART_1_INST`，`printf` 即发送） |
| 方向 | MSPM0 TX → ESP32-C3 RX（单向遥测；ESP32 无需回发） |
| 波特率 | 与现有 UART1 配置一致（见 `empty.syscfg` UART_1，默认 115200） |
| 电平 | 3.3V TTL，**必须共地** |
| 发送节拍 | MSPM0 主循环节拍，非等间隔。ESP32 端须用**自己的接收时间戳**标记每帧到达时间 |

> 注意：UART1 原为蓝牙 APP 口，现已改为遥测专用。MSPM0 端不再发 `{A}/{B}/{C}` 格式的 APP 帧。

## 帧格式

一行一帧，ASCII，逗号分隔，`\n`（0x0A）结尾：

```
$D,<G>,<P>,<Z>,<LT>,<RT>,<LS>,<RS>\n
```

| 字段 | 含义 | 类型/单位 | 范围参考 |
|---|---|---|---|
| `$D` | 帧头（Debug），过滤用 | 固定字符串 | — |
| `G`  | 8 路灰度掩码 | 无符号整数 0~255，bit0=通道0…bit7=通道7，1=黑线 | 0~255 |
| `P`  | 软化后线位置 | 整数 mm，负=偏左，正=偏右 | 约 −42~+42 |
| `Z`  | 角速度指令 | 整数 mrad/s（原始 rad/s ×1000） | 约 −3200~+3200 |
| `LT` | 左轮目标速度 | 整数 mm/s（原始 m/s ×1000） | 约 −350~+350 |
| `RT` | 右轮目标速度 | 整数 mm/s | 约 −350~+350 |
| `LS` | 左轮实际速度 | 整数 mm/s | 约 −350~+350 |
| `RS` | 右轮实际速度 | 整数 mm/s | 约 −350~+350 |

全部为整数，无浮点。示例：

```
$D,8,0,0,105,105,103,106
$D,4,-18,272,81,129,80,127
$D,16,18,-272,129,81,127,80
```

## 解析约定

1. 按 `\n` 切行。
2. 丢弃不以 `$D` 开头的行（防止上电噪声、半帧）。
3. 按 `,` 分割，字段数必须为 **8**（`$D` + 7 个数值），否则丢弃该帧。
4. 数值用 `atoi` / `toInt()` 解析为有符号整数。
5. 每帧记录 ESP32 本地接收时间戳（`millis()`），用于和 JY62 数据按时间对齐。

### Arduino 参考骨架

```cpp
// UART1 ← MSPM0，波特率与 MSPM0 UART1 一致（默认 115200）
void setup() {
  Serial0.begin(115200);   // 接 MSPM0 的口（按实际引脚/Serial 号调整）
  Serial.begin(115200);    // USB 调试输出
}

void loop() {
  static char buf[80];
  static uint8_t idx = 0;
  while (Serial0.available()) {
    char c = Serial0.read();
    if (c == '\n') {
      buf[idx] = '\0';
      idx = 0;
      if (buf[0] == '$' && buf[1] == 'D') {
        uint32_t t = millis();
        int G, P, Z, LT, RT, LS, RS;
        // 跳过 "$D," 后按 7 个整数解析
        if (sscanf(buf + 3, "%d,%d,%d,%d,%d,%d,%d",
                   &G, &P, &Z, &LT, &RT, &LS, &RS) == 7) {
          // 转发 / 记录：t, G, P, Z, LT, RT, LS, RS
          Serial.printf("%lu,%d,%d,%d,%d,%d,%d,%d\n", t, G, P, Z, LT, RT, LS, RS);
        }
      }
    } else if (idx < sizeof(buf) - 1) {
      buf[idx++] = c;
    } else {
      idx = 0;  // 溢出保护，丢弃超长行
    }
  }
}
```

## 用途：定位直线摆动根因

配合 `ques1.md` 的判断，直线段观察：

1. **G 在相邻单灯间跳变**（如 `0x08↔0x04` 即 `8↔4`，或 `0x10↔0x20` 即 `16↔32`）
   → 相邻单灯切换是当前软化遗漏的核心，问题在转向层。
2. **G/P/Z 已稳定但 LS/RS 仍摆或周期性接近零**
   → 问题在速度环/编码器/电机执行链，不再盲调巡线权重。
3. **LT/RT 连续但 LS/RS 跟不上或单轮掉零**
   → 速度闭环或硬件（TB6612、供电、机械阻力）问题。

## 已知限制

- 主循环节拍发送，**非等间隔**；`printf` 阻塞发送（一帧约 40 字节，115200 下约 3.5ms），实际帧率受 OLED 刷新等主循环负载影响。
- 未发 PWM。如需 PWM，须在 MSPM0 的 5ms 中断里缓存 `Set_PWM` 入参到全局变量，再在 `APP_Show` 里发送——当前未实现。
- 时间同步靠 ESP32 本地时间戳，与 MSPM0 内部 5ms 节拍无硬件同步；用于趋势/位型分析足够，不能做精确相位分析。
