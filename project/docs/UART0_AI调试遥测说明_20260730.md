# UART0 AI 调试遥测说明

> 最后更新：2026-07-31 10:55

## 目的

MSPM0 将 K230 视觉帧、同一时间窗内的双编码器增量、舵机命令和串口链路状态汇总到一条时间轴。串口助手保存原始 TXT 后，可直接交给 AI 判断问题更接近视觉、通信、控制输出还是机构没有响应。

## 接线与串口参数

```text
MSPM0 PA10 / UART0_TX -> USB-TTL RX
MSPM0 PA11 / UART0_RX <- USB-TTL TX（当前只采集日志时可不接）
MSPM0 GND             -> USB-TTL GND
```

使用 3.3 V TTL，配置为 115200、8 数据位、无校验、1 停止位。UART0 内部回环必须关闭。

K230 链路仍使用 UART1：

```text
K230 IO40 / UART1_TX -> MSPM0 PB7 / UART1_RX
K230 IO41 / UART1_RX <- MSPM0 PB6 / UART1_TX
```

## K230 到 MSPM0 的帧

```text
$K230,BALL,<x10>,<valid>,<seq>,<edge>*<crc8>#
```

- `x10`：K230位置毫米值乘 10，避免小数点丢失后仍被误解析。
- `crc8`：CRC-8/ATM 两位十六进制校验，覆盖 `$` 后到 `*` 前的 ASCII 字节。
- MSPM0 要求固定字段数，同时检查CRC、`x10=±1500` 范围、`valid` 和 `edge`。错误帧绝不更新控制输入。
- 原始像素、FPS和K230本地时间不再占用20 Hz闭环帧；它们保留在K230预览和TXT日志中，使用 `seq` 与M0日志对应。

## MSPM0 到电脑的帧

程序上电立即输出字段表，并每 5 秒重发一次：

```text
#TELEM_V3,t_ms,dt_ms,rx_ms,rx_age_ms,seq,x10,valid,edge,v10,toward_v10,stop10,trim10,wheel_enc_valid,wheel_encA_raw,wheel_encB_raw,servo_us,out10,ctrl,parse_err,crc_err,range_err,seq_gap,rx_overrun,timeout#
```

之后每 50 ms 输出：

```text
$T,50,50,45,5,1,42,1,0,0,0,0,900,0,3,-2,1653,96,2,0,0,0,0,0,0#
```

| 字段 | 含义 |
| --- | --- |
| `t_ms` | MSPM0 上电后的相对毫秒时间 |
| `dt_ms` | 本行编码器累计窗口的实际长度，正常约 50 ms |
| `rx_ms` | MSPM0 解析该视觉帧的本地时刻 |
| `rx_age_ms` | 输出本行时最近视觉帧的年龄；首帧前为 `-1`，时基相差一个5 ms节拍时饱和为 `0` |
| `seq` | K230 视觉帧序号 |
| `x10` | 小球位置毫米值乘 10，例如 `42` 表示 `+4.2 mm` |
| `valid` | `1` 为可靠检测，`0` 为保持/丢失或链路失效 |
| `edge` | `-1` 左边缘、`+1` 右边缘、`0` 非边缘 |
| `v10` | 滤波后小球速度（mm/s）乘 10；向右为正 |
| `toward_v10` | 朝当前目标方向的速度（mm/s）乘 10；大于 0 表示正在回中 |
| `stop10` | 由当前回中速度估计的制动距离（mm）乘 10 |
| `trim10` | 动态平衡角度（°）乘 10；90°只是上电种子，不是固定平衡值 |
| `wheel_enc_valid` | 当前底盘轮编码器是否确认接入本机构；现阶段固定为 `0` |
| `wheel_encA_raw`、`wheel_encB_raw` | `dt_ms` 窗口内底盘两路轮编码器原始累计增量；不是舵机角度，`wheel_enc_valid=0` 时仅用于观察悬空或电气干扰 |
| `servo_us` | 实际写入舵机 PWM 的高电平脉宽，单位 μs |
| `out10` | 控制器相对动态 `trim` 的快速纠偏角度乘 10 |
| `ctrl` | 控制状态编码，见下表 |
| `parse_err` | MSPM0 累计 K230 帧解析错误数 |
| `crc_err` | 字段看似完整但CRC不匹配的累计帧数 |
| `range_err` | CRC正确但位置、有效位或边缘组合越界的累计帧数 |
| `seq_gap` | 根据 K230 序号发现的累计缺帧数 |
| `rx_overrun` | MSPM0 UART1 接收环形缓冲累计溢出数 |
| `timeout` | `1` 表示超过 100 ms 未收到有效 K230 帧 |

控制状态：

| `ctrl` | 状态 |
| ---: | --- |
| 0 | `OFF`，闭环关闭 |
| 1 | `CAP`，中心附近低速捕获，并允许慢速学习 `trim` |
| 2 | `ACC`，持续施加起动力，直到确认球向中心运动 |
| 3 | `RUN`，保持球滚动并向中心推进 |
| 4 | `BRK`，按估算制动距离反向制动 |
| 5 | `EDGE`，视野边缘恢复 |
| 6 | `FLT`，规定时间内仍未确认运动 |
| 7 | `HOLD`，短时普通丢帧，冻结状态并保持上次安全输出 |
| 8 | `LOST`，持续丢帧，回到当前动态 `trim` |

## 采集与交给 AI

1. 先连接串口助手，再复位 MSPM0，确认能看到 `#TELEM_V3`。
2. 开启“保存接收数据到文件”，关闭十六进制显示，不要删除 `$T`、`#` 或字段表。
3. 至少记录一次小球静止、开始运动、越过中心和重新稳定的完整过程。
4. 把 TXT 原样交给 AI，并说明实验中球的初始位置、是否触碰机构、是否手动干预。

发送周期目标为50 ms；OLED和阻塞式UART输出会使实测 `dt_ms` 大于50 ms，分析编码器时以每行实际 `dt_ms` 为准。当前Keil构建已通过（`0 Error(s), 0 Warning(s)`）；UART0 `TELEM_V3`、动态平衡角与混合控制仍需实机验证。
