## 1. 调研结论

本题已有大量往届作品可借鉴，但不能直接照搬。各队主控、传感器和赛道实现不同，公开报告中的“可行”只说明其在原队硬件、光照和机械结构下有效；本项目必须以 MSPM0G3507、现有差速底盘和 K230 为基线重新验证。

对本项目最有价值的共识如下：

1. 单车基础部分应优先做成闭环状态机，而非把数字识别、巡线、装卸检测分别孤立调通。
2. 红线识别是最高风险项。公开作品对红外/灰度方案的结论并不一致，说明必须先进行实测，不能直接沿用黑线参数。
3. 病房数字宜在药房静止阶段完成识别并锁定，行驶中依赖路线表、路口与里程/门口判据导航，可减少视觉实时性的压力。
4. 药物装卸检测的公开方案包括压力、微动开关、红外遮挡和超声；本项目应以“抗振动、可重复、可安装”为选型标准。
5. 公开代码主要适合作为模块思路、接口和测试方法参考；必须确认许可、芯片平台和硬件接线后才可复用。

## 2. 题目与验收边界

官方题面要求小车在药房识别 1–8 号病房、检测约 200g 药品装载后自动沿红线送达、到房停车亮红灯、卸载后返回药房并亮绿灯；近端、中部、远端任务的送达和返回均要求小于 20 秒。[官方题面](https://nuedc.org/problems/2021_F%E9%A2%98_%E6%99%BA%E8%83%BD%E9%80%81%E8%8D%AF%E5%B0%8F%E8%BD%A6.pdf)

因此本项目基础部分的最小闭环为：

```text
识别病房号 → 锁定目标 → 检测装载 → 红线巡线/寻径 → 门口到位
→ 停车亮红灯 → 检测卸载 → 返程巡线/寻径 → 药房到位 → 停车亮绿灯
```

双车协同、无线通信与暂停调度属于后续发挥部分，不应阻塞单车基础闭环。

## 4. 往届方案调研

### 4.1 巡线与定位

| 公开案例 | 方案/现象 | 对本项目的启示 |
| --- | --- | --- |
| [北京林业大学作品](https://www.eetree.cn/project/737) | 报告指出红外对红白区分精度不足，改用灰度传感器并增加遮光罩；使用 HX711 压力传感器检测约 200g 药品。 | 可将“灰度 + 遮光”作为 Task 1 的候选方案，但仍须在本车、实际红线下测量。 |
| [中国石油大学（华东）作品](https://www.eetree.cn/project/706) | 报告称红黑边界反射强度差异不明显，红外寻迹灵敏度不足。 | 反向证明传感器和场地的光谱匹配不可假设；红线与黑线更不能共用固定电平。 |
| [南信大作品](https://www.eetree.cn/project/detail/811) | 红线巡线不稳定时改用 MT9V03X 视觉巡线。 | 若 8 路传感器失败，可评估“主控巡线 + 视觉辅助”或改用专用摄像头，但会显著增加系统复杂度。 |
| [立创国一作品](https://oshwhub.com/2021yin-long-dui/2021-dian-saif-ti-zhu-kong-ban) | 采用带 MCU 的红外循迹模块与陀螺仪转向闭环。 | 陀螺仪可作为转向动作的辅助闭环，不替代红线横向误差检测。 |

**项目决策：** 先执行 `task1.md`。只有红线与底色的稳定输出差足够大时，才在 MSPM0 上复用现有 8 路巡线框架；否则在文档中记录失败数据并切换方案。

### 4.2 病房数字识别与主控通信

| 公开案例 | 方案/现象 | 对本项目的启示 |
| --- | --- | --- |
| [中国石油大学（华东）作品](https://www.eetree.cn/project/706) | 使用 K210/KPU 训练数字 1–8。 | 与本项目 K230 检测模型的职责相同：识别仅应输出目标编号。 |
| [南京大学金陵学院作品](https://www.eetree.cn/project/detail/788) | K210/OpenMV 识别结果交给主控，主控负责运动决策。 | 保持“视觉识别、主控决策、电机闭环”分层，避免 K230 直接驱动电机。 |
| [黑龙江大学作品](https://www.eetree.cn/project/723) | OpenMV 识别结果经主控进行 PWM 控制，采用超声判断药物有无。 | 可参考“视觉只传结果”的接口思想；超声方案需单独评估遮挡和误触发。 |

**项目决策：** 固定使用 K230 作为数字识别设备，不替换为 K210/OpenMV。复用 `K230_UART_Demo` 的链路机制，在其上新增病房号、置信度/有效标志和主控连续确认逻辑；不要照搬其他平台的模型或驱动代码。

### 4.3 装载/卸载检测

| 方案 | 公开依据 | 优点 | 主要风险 |
| --- | --- | --- | --- |
| 压力传感器 + HX711 | [北京林业大学作品](https://www.eetree.cn/project/737) | 与“约 200g”要求直接对应，可设置质量阈值 | 机械安装、标定、振动滤波和 ADC/通信资源。 |
| 微动开关 | [立创国一作品](https://oshwhub.com/2021yin-long-dui/2021-dian-saif-ti-zhu-kong-ban) | 简单、响应快、易由 GPIO 读取 | 只反映放置，不反映实际质量；需防止药盒位置偏差。 |
| 红外/超声遮挡 | [山东大学作品](https://www.eetree.cn/project/751)、[黑龙江大学作品](https://www.eetree.cn/project/723) | 成本低、接入简单 | 药盒外形、摆放位置和环境反射会影响可靠性。 |

**建议：** 若机械结构允许且追求题意一致，优先比较压力传感器与微动开关；先用空载、200g、振动、偏置摆放四组测试数据决定，不在代码中硬编码未经标定的阈值。

### 4.4 路径规划与状态机

公开作品通常通过“目标编号 → 路口动作序列 → 门口停车 → 原路返回”完成基础任务；也有作品在行驶中结合视觉识别路标。前者更适合本项目，因为病房号在药房可先锁定，MSPM0 可在 5ms 控制环中保持确定的巡线与转向动作。

本项目采用 `medicine_task + route + line_follow` 分层：

- `medicine_task` 决定何时允许出发、到房等待和返回；
- `route` 保存 1–8 号去返路线与门口到位条件；
- `line_follow` 仅产生沿红线运动请求；
- 编码器里程可辅助纵向定位，但门口到位不能仅依赖预计运行时间。

## 6. 不建议直接复用的内容

- 不复制 STM32、MSP432、MM32 等平台的底层驱动、定时器配置、PWM 初始化或中断代码。
- 不将外部 K210/OpenMV 模型、类别顺序或阈值直接覆盖当前 K230 模型配置。
- 不依赖外部作品的速度、PID、里程或门口距离参数；这些均受电机、轮径、地面和车体结构影响。
- 不把报告中的测试结果视为本车验收结果；每项必须在本车和本场地复测。
- 不下载或提交许可证不明的整包代码、二进制模型或资料附件。

## 7. 对后续任务的输入

| 任务 | 调研后的行动 |
| --- | --- |
| Task 1 | 测试“8 路灰度 + 遮光”对红线的实际效果；失败则评估替代巡线传感器。 |
| Task 2 | 在现有 UART 握手之上增加识别结果帧，主控锁定稳定编号。 |
